Part 1: Dependency Analysis (package.json)
Before diving into individual files, let's understand the runtime ecosystem. Our dependencies are handpicked to deliver a 60fps cinematic frame-budget:
react & react-dom (v18+): Core UI fiber engine. Leverages virtual DOM transitions and state-driven reconciliation.
lucide-react: Flat, minimalist SVG vector icons. Imported as named elements to ensure the compiler bundle utilizes tree-shaking (removing unused icons).
lenis: The premier lightweight smooth-scrolling library. Replaces the browser's native rigid scrolling mechanics with an interpolated, momentum-driven animation cycle, mirroring premium luxury/web-agency interfaces.
Tailwind CSS: A utility-first CSS framework. Used in conjunction with our modern @import configuration to compile class arrays into highly optimized, tiny stylesheets without any styling runtime cost.
Vite: The ultra-fast ESM-based bundling tool. Builds, rolls, and bundles assets with Zero-Config Hot Module Replacement support.

File Overview: src/components/MagneticButton.tsx
Purpose
Provides a delightful, highly responsive, micro-interactive magnetic effect on buttons when the mouse cursor enters their radial field. It captures pointer coordinates relative to the button's geometric center and interpolates the container's transformation on the GPU canvas.
Connections to other files

Acts as a wrapper over standard buttons to elevate their feel.

None. Pure hardware-accelerated CSS and modern React pointers.
Imports

Exports
default function MagneticButton — Fully customizable premium interactive element.
Component Props

className (string, optional): Additional Tailwind spacing classes.
onClick (() => void, optional): Success feedback trigger.
id (string, optional): HTML unique targeting identifier.
type ("button" | "submit", optional): Native form submit identifier.
Functions
handleMouseMove (Inside useEffect)
Purpose: Calculates the cursor hover position offset from the exact center of the button, translating that into tiny, sophisticated coordinate movements.
Inputs: e: MouseEvent (Mouse positioning object).
Outputs: None. Updates internal React state.
Side effects: Triggers component re-render on mouse movement, updating inline styles.
When it runs: Continually on pointer-move when cursor is hovering within the element's bounding box.
Hooks Used
useRef<HTMLButtonElement>: Targets the direct DOM element to calculate getBoundingClientRect() values.
useState({ x: 0, y: 0 }): Maintains current translation coordinate state.
useEffect(): Registers the global pointer-listeners securely. Cleans up event listeners on dismount to prevent memory leaks.
Styling & CSS approach
Reduces the coordinate range multiplier directly to 0.22 (i.e. maximum 10-12px shift) to prevent exaggerated cartoon jumping. Utilizes Tailwind-guided hardware acceleration via will-change-transform and elegant cubic-bezier(0.16, 1, 0.3, 1) transitions for instantaneous snap-backs.

Database Preparation Guide
To evolve this single-view cinematic prototype into a multi-user operational system handling real-world reservations, we should implement a secure database strategy. Here is our architectural recommendation for migrating the client-side data states:
1. Data That Must Move to the Database
Physical Ticket Registrations: Names, Emails, cryptographic UUID Serial numbers, Check-in status, and chosen Event IDs.
Capsule Merch Active Inventory: Stock statuses, sizes pool, price models, and reservation queue counters.
Cast Dossiers Assignment Engine: Stores which ticket/user is dynamically mapped to which CharacterCard of the live script to guarantee no duplicate role assignments occur at the door.

3. Suggested API Routing Layer (Express backend middleware)
POST /api/tickets/compile: Validates email formats, checks if event spots are remaining, registers the ticket record in Firestore, and returns structural JSON detailing compile locks.
GET /api/tickets/verify/:serial: Door scan API endpoint. Handled by coordinators to toggle the checkedIn bool flag on entry.
POST /api/merch/reserve: Registers pre-order item inquiries directly to database locks.
GET /api/characters/assign: Implements custom atomic server transactional controls to draw an unassigned roleplay dossier, locks assignment to the buyer, and delivers it securely.
4. Suggested Authenticated Control Flow
We recommend utilizing Firebase Authentication alongside our Firestore configuration rules. Under this standard model:
Generics / Guest views: Publicly readable. Guests can view merchandise lists, read live story pillars, and access the ticketing compile form.
Ticket Holders: Can query and view their personal assigned secrets dossier. Protected with basic security token structures containing unique access IDs.
Organizers / Coordinators UI: Authorized admin accounts. Fully allowed to write, modify, and check-in tickets.
